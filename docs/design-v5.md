# アサエール ラウンド4.5修正＋ラウンド5設計（2026-11-28 本人指示）

## ラウンド4.5 修正（ラウンド5の前に実施）

### FIX-1 登録フォームから詳細欄を削除
- 本人の指示（2026-11-28 12:29、実機スクリーンショット）：目標登録フォームの「詳細」欄を消す
- 対応：登録フォームから詳細の入力欄を削除し、登録は「ニックネーム（ラウンド5でアカウント名へ移行）／種類／タイトル／起床予定／公開設定」だけにする
- DBの detail 列は残す（過去に登録された夢の詳細は、応援画面・フィードで今まで通り表示する。新規登録では detail は空になる）
- 公開範囲の説明文から「詳細」の記載を外す

### FIX-2 どのページにも常にナビゲーションバーを表示
- 本人の指示（2026-11-28 12:29）：応援ページ（/s/:supportToken）にもナビを設置し、**全ページで常に下部ナビを表示**する
- これまでの例外（応援画面は外部向けのためナビなし）は廃止する
- 対象は全ルート：`/`（登録）、`/share/:goalId`（共有）、`/s/:supportToken`（応援）、`/o/:ownerToken`（受信）、`/feed`（みんなの夢）、`/me`（プロフィール）

## ラウンド5 ユーザー登録（端末ベース）

方針（2026-11-28 本人決定）：ユーザー登録は「端末ベース→メールログイン」の順。第1段の端末ベースをこのラウンドで実装する。メールログインは次ラウンド。

### 設計
- 初回利用時に端末ID（推測困難なランダムID）を発行し、端末内（localStorage、データ層管理）に保持する
- 利用者は「アカウント名」（20文字まで）を設定できる。プロフィール画面でいつでも変更可能
- アカウント情報は Supabase の `asayell_profiles` テーブルに保存し、RPC経由でのみ読み書きする（device_id を鍵にする。device_id は推測困難な値で、現行の owner_token と同水準の扱い）
- 夢の登録時に端末IDを紐づける（`asayell_goals.owner_device_id`）。登録時の表示名はアカウント名をサーバ側で採用する
- **ニックネーム欄の廃止**：登録フォームからニックネーム入力をなくし、アカウント名を自動で使う。アカウント名が未設定の場合は、登録の前にアカウント名の設定を促す（プロフィール画面へ誘導、またはフォーム上でその場で設定）
- プロフィール画面（/me）：アカウント名の表示・変更、自分の夢の一覧を端末IDで引いて表示する。従来の owner_token で控えた過去の夢も引き続き表示される（移行互換）
- フィード・応援画面の表示名はアカウント名（DB上は従来どおり nickname 列に保存して表示互換を保つ）

### SQL（Muse作成・本人がSQL Editorで適用）
- `supabase/migrations/20261128040000_asayell_profiles.sql`
  - `asayell_profiles` テーブル（device_id 主キー、account_name、created_at/updated_at）、RLS有効・直接ポリシーなし
  - RPC：`asayell_upsert_profile(p_device_id, p_account_name)`、`asayell_get_profile(p_device_id)`、`asayell_list_my_goals(p_device_id)`
  - `asayell_goals.owner_device_id` 列の追加、`asayell_create_goal` に `p_device_id` を追加（指定時はプロフィールのアカウント名を nickname に採用）

### 不合格条件の追加（ラウンド5）
- 他人の端末IDで、その人の夢一覧やアカウント名が取得できる（推測困難でないIDの使用）
- アカウント名未設定のまま、誰の夢か分からない状態で登録できる
- 従来の owner_token で作った夢がプロフィールから見えなくなる（移行互換の欠落）
