# アサエール ラウンド4設計メモ（2026-11-28 本人の実機フィードバック）

前提：ラウンド3（公開フィード＋ナビ＋プロフィール）完了後。本メモは本人が実機スクリーンショットで指摘した4点と、ユーザー登録の相談を設計に落としたもの。

## FB-1 共有画面にもナビを出す
- 現象：夢を投稿した直後の共有画面（/share/:goalId）で下部ナビが消える
- 対応：共有画面にも下部ナビを表示する（投稿フローは「投稿」タブ配下として扱う）。応援画面 /s/ は外部向けなので従来どおりナビなし

## FB-2 プロフィールのURL表示を省略
- プロフィール画面ではURL文字列そのものは表示しない。「応援募集URLをコピー」「受信画面を開く」ボタンだけ残す
- 共有画面（投稿直後）のURL表示は、初回に渡す必要があるため残すかは実装時に再確認（本人の意図はプロフィールの省略）

## FB-3 登録フォームの改善
- 詳細欄に薄文字（プレースホルダ）で入力例を示す。例：「例）まずは布団から出て水を飲む。小さな一歩でOK」
- 夢・目標・楽しみを「種類」として記録できるようにする：登録時に 夢／目標／楽しみ のチップから1つ選ぶ（カテゴリ）。フィードやプロフィールで種類が分かる表示にする。将来はカテゴリでフィードを絞れる土台にする
- ニックネーム欄の廃止はユーザー登録（FB-5）とセット。アカウント名を使う設計に移行してから外す（順序を間違えると誰の夢か分からなくなる）

## FB-4 みんなの夢はリスト形式フィードに変更
- 現行のリール（1件ランダム表示）をやめ、登録された公開夢が縦に並ぶリスト形式にする（SNSのフィード投稿のイメージ）
- カード構成は現行踏襲：投稿者名（将来はアカウント名）、種類（夢／目標／楽しみ）、タイトル、詳細、起床予定、届いた応援数、「応援する」ボタン
- 並びは新着順を基本とする。公開OFF・起床済みは出さないルールは維持

## FB-5 ユーザー登録（相談事項・ラウンド5候補）
- 可能。Supabase Auth（無料枠）を使う前提で3方式：
  1. 端末ベース：今の owner_token 控えを正式な「マイID」に昇格。登録不要で今の体験を維持できるが、端末を変えると引き継げない
  2. メールログイン（マジックリンク）：Supabase Auth の標準機能で実装でき、端末間同期が可能。メール送信は無料枠の範囲
  3. Googleログイン：Supabase Auth＋Google OAuth。手軽だが設定手順が増える
- **決定（2026-11-28 本人）：端末ベース→メールログインの順で進める**。まず端末ベースで「アカウント名」を持てるようにし、次にメールログイン（Supabase Auth マジックリンク）で端末間同期を追加する。移行時は既存の夢（owner_token）をアカウントに紐づけられるようにする
- アカウント導入後にやること：ニックネーム欄の廃止（アカウント名に統一）、プロフィールのアカウント名表示

## FB-6 起床時の通知（将来候補）
- 「エールが届いた」ことを朝に通知する Web Push は技術的に可能（Service Worker＋購読＋送信ジョブ。送信側は Supabase Edge Functions＋定期実行で無料枠内を想定）
- ただし元の仕様の決定「アサエールは目覚まし時計ではない（アラームは作らない）」とは緊張関係がある。通知は「起こす」ではなく「届いたことを知らせる」に留める設計なら両立しうる。本格検討はラウンド5以降

## ラウンド分割（案）
- ラウンド4：FB-1（ナビ）、FB-2（URL省略）、FB-3（プレースホルダ＋種類チップ）、FB-4（リストフィード）
- ラウンド5：FB-5（ユーザー登録）、ニックネーム廃止、FB-6（通知）の要否判断
